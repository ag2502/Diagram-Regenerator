# Quickstart example: Taskboard

A small SaaS schema (organisations, projects, tasks, billing) kept as Flyway-style
PostgreSQL migrations in [`db/migrations`](db/migrations). Everything under
[`docs/schema`](docs/schema) is generated by Diagram Regenerator:

| File | What it is |
| --- | --- |
| [`docs/schema/README.md`](docs/schema/README.md) | ER diagram (overview + one per area) and the data dictionary; GitHub renders it in place |
| [`docs/schema/index.html`](docs/schema/index.html) | Searchable, zoomable schema browser (download and open it) |
| [`docs/schema/schema.json`](docs/schema/schema.json) | The snapshot that pull requests are compared against |
| [`docs/schema/schema.dbml`](docs/schema/schema.dbml) | The same schema for [dbdiagram.io](https://dbdiagram.io) |
| [`docs/schema/descriptions.yml`](docs/schema/descriptions.yml) | Human-reviewed descriptions; two entries are still `[draft]` |
| [`sample-pr-comment.md`](sample-pr-comment.md) | The comment a PR adding `V4__due_dates_and_audit.sql` receives |

Try it from this folder:

```bash
diagram-regen generate                            # rewrites docs/schema (no changes expected)
diagram-regen check                               # what CI runs: exits 1 if docs are stale
diagram-regen describe --provider heuristic --dry-run
diagram-regen render db/migrations -f mermaid     # print the diagram
```

Add a migration (say `V5__labels.sql` with `ALTER TABLE tasks ADD COLUMN label text;`) and run
`diagram-regen diff` to see how the change is rated, then `diagram-regen generate` to update the docs.
